# 图片与公式图题

v1.1 支持接收 OCS 的图片参数，并将图片按顺序传入模型的 `image_url` 内容块。图片中的公式、题干和选项由模型识别。

## 从旧版本升级

1. 关闭正在运行的本机题库服务窗口。
2. 更新程序文件，保留自己的 `data/` 文件夹，避免覆盖已有网关设置、密钥和题库。
3. 重新运行 `start.cmd` 或 `node server.mjs`，刷新 <http://127.0.0.1:8765/>。
4. 点击「复制题库配置」，将新版完整 JSON 粘贴到 OCS 的题库配置区，解析器选择「默认」后保存。
5. 开启 OCS 的「图片题优化」，再查询一张清晰的图片题。

只更新文件、没有重启服务时，仍会运行旧的后端代码。只更新程序、没有重新复制配置时，OCS 仍然不会传递图片。

## 为什么旧配置会弹出提示

v1.0 的配置仅包含 `title`、`options`、`type`。OCS 检测不到图片参数时，会提示「当前题库配置暂不支持图片、公式等题目处理」。

新版采用 POST，并实际引用以下字段：

```json
{
  "title": "${title}",
  "options": "${options}",
  "type": "${type}",
  "images": {
    "handler": "return (env)=> env.images || []"
  },
  "suggestion_title": "${suggestion_title}",
  "suggestion_options": "${suggestion_options}"
}
```

这是完整配置中 `data` 字段的示例，不是可单独粘贴的完整题库配置。请使用设置页生成的完整配置，它会包含本机的独立连接令牌。

`images` 是 base64 data URL 数组。`suggestion_title` 和 `suggestion_options` 使用 `[图片1]`、`[图片2]` 等标记，与数组中的图片顺序对应。服务不会把这些图片仅作为 JSON 文本发送，而是构造真实的多模态消息。

## 使用条件与限制

- 模型和网关必须支持图片输入。本项目已通过当前 WorkBuddy Gateway 的 `deepseek-v4.1-flash` 验证，其他模型需要自行测试。
- 每题最多 8 张图片，单张不超过 4 MiB，总计不超过 8 MiB。
- 支持 PNG、JPEG、WebP、GIF。公式的 SVG 或其他格式应由 OCS 转为受支持的位图。
- 图片下载失败、标记与图片数量不对应时会返回错误，不会只依据残缺文字生成答案。
- 图片和公式识别可能出错，尤其是模糊的小字、复杂图表和多步骤推导，需核对解析。

## 在设置页测试

在「验证一道题」中选择题型、填写题干和选项，然后在「题目图片」中选择图片。题干与选项可使用 `[图片1]` 等标记。

例如，题干填写「计算 [图片1] 中的定积分」，选项每行一个，再上传公式图片进行查询。单选、多选题仍需要提供选项文本，选项本身是图片时可写成 `A. [图片2]`、`B. [图片3]` 等。

图片内容参与缓存键计算，所以同样的题干更换图片后会重新调用模型。缓存只保存答案、解析和图片数量，不存储原始图片。
